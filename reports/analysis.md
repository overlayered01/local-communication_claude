# 1차 비교 분석 (2026-09-15)

환경: RTX 5080 16GB, Windows 11, Ollama 0.34, Python 3.11 / torch 2.11+cu128.
수치 원본은 `summary.md`(자동 생성)와 `results.jsonl`, 채점 원본은 `judge.jsonl`, 청취용 음성은 `audio/<option>/`.

## 결론 요약

| 구성 요소 | 1차 추천 | 근거 | 대안 |
|---|---|---|---|
| LLM | **Qwen3 8B** (think off) | 품질 상위권(4.80), 첫 토큰 286ms, 128 tok/s, VRAM 6.4GB로 TTS와 여유 있게 공존 | Gemma3 12B: 품질 1위(4.81)지만 VRAM 9.6GB, 생성 94 tok/s, 이모지 남발 |
| TTS | **Supertonic 3 (GPU)** | 문장당 195ms로 길이 무관, RTF 0.03, CER 0, VRAM 1.4GB, 44.1kHz | MeloTTS KR: 298ms, VRAM 1GB, 억양은 청취 평가 필요 |
| STT(평가용) | faster-whisper large-v3-turbo | 한국어 전사 정확, GPU 2.1GB | - |
| E2E 조합 | **Qwen3 8B + Supertonic GPU** | 첫 음성 827ms(p95 901ms), 총 VRAM 8.5GB | Qwen3 8B + MeloTTS: 첫 음성 599ms로 더 빠름 |

## LLM

| option | ttft_ms | tok/s | VRAM(MB) | 품질(mean) | 간결성 |
|---|---|---|---|---|---|
| exaone3.5 7.8B | 284 | 197 | 5874 | 4.71 | 4.21 |
| gemma3 12B | 329 | 94 | 9597 | 4.81 | 4.83 |
| llama3.1 8B | 280 | 148 | 5957 | 4.49 | 4.38 |
| qwen3 14B | 291 | 80 | 10325 | 4.68 | 4.38 |
| qwen3 8B | 286 | 128 | 6352 | 4.80 | 4.58 |

- 첫 토큰 지연은 모델 크기와 무관하게 280~330ms로 사실상 동일합니다. Ollama의 프롬프트 처리 오버헤드가 지배적이라, LLM 선택은 지연이 아니라 품질과 VRAM으로 결정하면 됩니다.
- EXAONE은 한국어 문법 5.00으로 가장 정확하지만 답이 길어(간결성 4.21, E2E 오디오 12초) 음성 대화에 불리합니다. 반말 맥락에서 존댓말로 전환하는 경우도 관찰되었습니다.
- Qwen3 8B는 "mong이" 같은 로마자 혼입, Qwen3 14B는 "잔반을 주고" 같은 어휘 오류가 한 번씩 관찰되었습니다. 샘플이 적어 빈도 판단은 추가 측정이 필요합니다.
- Gemma3 12B와 Qwen3 8B는 이모지를 자주 붙입니다. 파이프라인이 TTS 전에 제거하지만, 시스템 프롬프트에 금지 문구를 넣는 것이 근본 해결입니다.
- 채점 모델이 Qwen3 14B라 자기 선호 편향 가능성이 있습니다. 14B 자신이 4위여서 편향이 크지는 않아 보이나, 더 큰 외부 모델로 재채점하는 것을 권합니다. 점수 분포가 4.2~5.0으로 압축되어 변별력이 낮습니다. 루브릭을 더 엄격하게 하거나 쌍대 비교(pairwise)로 바꾸는 것을 검토합니다.

## TTS

| option | 문장당 ms | RTF | CER | VRAM(MB) | 비고 |
|---|---|---|---|---|---|
| supertonic (GPU) | 195 | 0.03 | 0 | 1368 | 길이 무관 상수 시간 |
| melotts_kr (GPU) | 298 | 0.05 | 0 | 981 | |
| sapi (CPU) | 463 | 0.1 | 0 (REST→"레스트" 0.13) | 0 | 하한 기준점 |
| edge (클라우드) | 563 | 0.1 | 0 | 0 | 네트워크 포함 |
| supertonic (CPU) | 2075 | 0.4 | 0 | 0 | 24코어에서도 느림. 스레드 튜닝 필요 |
| supertonic M1 4-step | 1658 | 0.3 | 0.04~0.08 | 0 | 스텝 줄이면 발음 오류 발생 |

- Supertonic은 GPU에서만 실용적입니다. CPU 경로가 예상보다 훨씬 느린데, intra-op 스레드 수 조정과 다른 다운로드와의 경합 여부를 재확인해야 합니다.
- 디노이징 스텝을 8에서 4로 줄이면 "3시"를 "세리시"로 읽는 식의 오류가 생깁니다. 8스텝을 유지합니다.
- 라운드트립 CER은 명료도 지표이며 자연스러움을 말해주지 않습니다. `audio/` 청취 평가가 반드시 필요합니다.
- CosyVoice2는 이번에 실행하지 않았습니다. 목소리 클로닝이 요구사항이면 별도 세션에서 설치와 측정이 필요합니다(VRAM 2~4GB 추가).

## E2E (문장 단위 스트리밍 파이프라인)

| 조합 | 첫 토큰 | 첫 문장 | 첫 음성 | 총 VRAM |
|---|---|---|---|---|
| qwen3 8B + melotts | 284 | 343 | **599** | 7533 |
| exaone + supertonic | 282 | 365 | 709 | 8092 |
| qwen3 8B + supertonic | 290 | 367 | 827 | 8498 |
| gemma3 12B + supertonic | 330 | 423 | 873 | 11622 |
| qwen3 14B + supertonic | 297 | 424 | 905 | 12421 |

- 첫 음성까지 600~900ms로 모두 1초 안에 들어옵니다.
- 첫 문장 완성(~370ms)과 첫 음성(~830ms) 사이 간격이 TTS 단독 지연(195ms)보다 큽니다. 파이프라인이 LLM 델타가 도착할 때만 완료된 오디오를 내보내는 구조여서 생기는 대기입니다. 오디오 큐를 독립 태스크로 분리하면 200ms 이상 줄일 수 있습니다.
- MeloTTS 조합이 첫 음성에서 더 빠른 것은 짧은 첫 문장에서 MeloTTS가 유리하기 때문입니다. 긴 문장에서는 Supertonic이 앞섭니다.

## 다음 단계

1. 청취 평가: `audio/supertonic_gpu`, `audio/melotts_kr` 8문장씩 3명 이상 MOS 채점.
2. 파이프라인 개선: 오디오 드레인을 독립 태스크로 분리해 첫 음성 지연 재측정.
3. 시스템 프롬프트 튜닝: 이모지 금지, 2문장 이내, 반말/존댓말 고정 후 judge 재실행.
4. 외부 judge로 재채점하거나 쌍대 비교로 전환.
5. 필요 시 CosyVoice2 측정, Supertonic CPU 스레드 튜닝.
